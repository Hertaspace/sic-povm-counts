# Publication disclosure scan

The publication payload was scanned during the publication-build checks: source programs, proof notes, documentation, data, historical outputs, generated inventories/bindings, all restored root blocks, every text stream after joining and decompressing multipart gzip, and every decoded member of the certificate attachment.

The restricted categories are specific language-model/provider identifiers, email addresses, private host names, private account names, workstation/server absolute paths, private executable paths, and Chinese text. All have **zero unresolved matches**. Structured `host`, `runtime_host`, and `hostname` metadata was checked separately. Historical values were normalized to `not-recorded`, and source programs no longer collect a runtime host name. Necessary proof explanations from internal records were rewritten in English.

The scan uses token boundaries for restricted identifiers, avoiding substring matches within mathematical words such as `solution`, `solve`, and the executable `msolve`. Binary compressed bytes are not misdecoded as text: joined streams and attachment members are decoded and checked. The selected compressed streams contain no Chinese proof annotations. Their bytes are unchanged.

The retained absolute names `/proc` and `/usr/lib/libproc.dylib` identify documented operating-system resident set size (RSS) interfaces in `replay/portable.py`. The replay notes also name `/usr/bin/time`, the public measurement tool used for wall times and peak RSS. These are operating-system paths. JSON Pointer strings beginning with `/` in `replay/bindings.json` locate fields inside records and are not filesystem paths. Schema names and mathematical source aliases are retained. These are the complete intentional path-like exceptions. The requested restricted categories have no retained matches.

Git metadata, ignored temporary replay workspaces, virtual environments, and interpreter caches are outside the publication payload. They are never part of the manifest or attachment and must not be transferred into the public repository. The clean-replay records in `replay/clean-run/` were not normalized. Their logs keep the workspace prefix `/home/ubuntu/counts-replay` of the disposable Linux replay environment, a default account name with no host name, so that every published byte still matches the hash recorded in `result.json`. The compiled support-census binaries and a process-ID file regenerated by that replay are not published.

Scan results establish disclosure hygiene under these rules. They do not verify the mathematical conclusions, renew historical success flags, or authorize publication. See [VALIDATION.md](VALIDATION.md) for the separate computational scope.
